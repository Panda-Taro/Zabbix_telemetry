# 導入手順書

Telemetry 中間サーバー(以下「中間サーバー」)を導入し、Cisco Nexusの監視データをZabbixへ送れるようにするまでの手順です。ITに詳しくない人でも進められるよう、1手順ずつ書いています。

この文書の中のホスト名やIPアドレス(NEXUS-TEST-01、192.0.2.10など)は、すべて説明のための例です。実際の値に置き換えてください。

## 1. 全体の流れ

```
(1) 中間サーバーに Ubuntu Server 24.04 LTS を入れておく
(2) 中間サーバーで、ソースコードをダウンロードし、deploy.sh を実行する   … 3章
(3) WebGUI にログインし、管理者のパスワードを変える                     … 4章
(4) Zabbix に、テンプレートを取り込み、「telemetry」ホストを登録する      … 5章
(5) WebGUI で、Zabbix サーバーの IPアドレスを設定する                    … 6章
(6) 機器(Nexus)を1台ずつ追加する                                       … 7章
```

## 2. 用意するもの

| もの | 内容 |
| :---- | :---- |
| 中間サーバー | Ubuntu Server 24.04 LTSを入れた、物理サーバーまたはHyper-Vの仮想マシン |
| インターネットへの接続 | 導入と更新のときだけ必要です。中間サーバーがインターネットに直接つながっていること(プロキシには対応していません) |
| 中間サーバーの管理者のアカウント | Ubuntuを入れたときに作ったユーザー名とパスワード(`sudo` が使えるもの) |
| Zabbix Server | Zabbix 7.0 LTS。管理者でログインできること |
| 運用者のPC | Google ChromeまたはMicrosoft Edgeが使えるPC |
| 決めておく値 | 中間サーバーのIPアドレス、デフォルトゲートウェイ、DNSサーバー、(社内にあれば)NTPサーバー |

### 通信の一覧

途中にファイアウォールがある場合は、次の通信を通してください。

| 通信元 | 通信先 | プロトコル/ポート番号 | 内容 |
| :---- | :---- | :---- | :---- |
| Cisco Nexus | 中間サーバー | UDP 50051(WebGUIで変更できます) | Telemetryのデータ |
| 中間サーバー | Zabbix Server | TCP 10051 | 監視データの送信 |
| 運用者のPC | 中間サーバー | TCP 8080(WebGUIで変更できます) | WebGUI |
| 中間サーバー | NTPサーバー | UDP 123 | 時刻同期 |

## 3. 中間サーバーへの導入

### 3.1 中間サーバーにログインする

次のどちらかの方法で、中間サーバーのコマンドを入力する画面を開きます。

- **中間サーバーのコンソール(画面とキーボード)で行う場合**:Ubuntuのユーザー名とパスワードでログインします。
- **運用者のPCからSSHで行う場合**:Windowsの「ターミナル」または「PowerShell」を開き、次のように入力します。`ユーザー名` と `192.0.2.10` は、実際の値に置き換えてください。

  ```
  ssh ユーザー名@192.0.2.10
  ```

  初めて接続するときに `Are you sure you want to continue connecting` と聞かれたら、`yes` と入力してEnterを押します。続けて、Ubuntuのパスワードを入力します(入力した文字は表示されません)。

### 3.2 ソースコードをダウンロードする

**手順1** 次のコマンドを入力してEnterを押します。ホームフォルダに `Zabbix_telemetry` というフォルダができます。

```
git clone https://github.com/Panda-Taro/Zabbix_telemetry.git
```

`git: command not found` と表示された場合は、先に次のコマンドでgitを入れてから、もう一度手順1を行います。

```
sudo apt-get install -y git
```

**手順2** できたフォルダに移動します。

```
cd Zabbix_telemetry
```

### 3.3 デプロイ用スクリプト(deploy.sh)を実行する

**手順1** 次のコマンドを入力してEnterを押します。パスワードを聞かれたら、Ubuntuのパスワードを入力します。

```
sudo bash deploy.sh
```

**手順2** スクリプトは、次の11の手順を順番に行います。各手順の始まりに `=== 手順 1/11:… ===` と表示され、終わると `→ 結果:…` と表示されます。初回は、コンテナを作る手順6で数分かかります。

| 手順 | 内容 | 入力 |
| :---- | :---- | :---- |
| 1 | 実行環境の確認(Ubuntu Server 24.04 LTSか、管理者権限か、インターネットにつながるか) | なし |
| 2 | Dockerの導入(入っていない場合だけ) | なし |
| 3 | データ用フォルダ(/data)の作成 | なし |
| 4 | 時刻同期(NTP)の設定と、UDPの受信バッファを広げる設定 | **NTPサーバー**(3.3.1) |
| 5 | ファイアウォールが有効な場合の、必要なポートの開放 | なし |
| 6 | コンテナの作成と起動 | なし |
| 7 | OSの起動時の自動起動の設定 | なし |
| 8 | 補助プログラムの配置と、補助プログラムが使う部品(python3-yaml)の確認 | なし |
| 9 | 復旧用コマンドの配置 | なし |
| 10 | 本体のIPアドレスの設定 | **IPアドレスを変えるか**(3.3.2) |
| 11 | 結果の表示(WebGUIの接続先、初期アカウント) | なし |

#### 3.3.1 手順4:NTPサーバーの入力

次のように聞かれます。

```
  今のNTPサーバー:Ubuntu標準のサーバー
  NTPサーバー(複数なら空白で区切る。Enterのみ:今のまま、default:Ubuntu標準に戻す):
```

| したいこと | 入力 |
| :---- | :---- |
| 今の設定のままにする(初回はUbuntu標準のサーバー) | 何も入力せずにEnter |
| 社内のNTPサーバーを使う | NTPサーバーのホスト名かIPアドレス(例:`192.0.2.123`)を入力してEnter。3つまで、空白で区切って入力できます |
| Ubuntu標準のサーバーに戻す | `default` と入力してEnter |

Ubuntu標準のサーバーはインターネット上にあります。運用中にインターネットへつながらない場合は、社内のNTPサーバーを指定してください。Zabbixに記録される時刻は中間サーバーで受信した時刻なので、中間サーバーの時刻が正しいことが大切です。

#### 3.3.2 手順10:本体のIPアドレスの設定

今の設定が表示されたあと、次のように聞かれます。

```
  本体のIPアドレスを変更しますか?(変更しない場合は Enter) [y/N]:
```

- **変えない場合**:何も入力せずにEnterを押します。
- **変える場合**:`y` と入力してEnterを押し、続けて次の3つを入力します。

  | 聞かれること | 入力の例 | 決まり |
  | :---- | :---- | :---- |
  | IPアドレス/プレフィックス長 | `192.0.2.10/24` | プレフィックス長は8〜30 |
  | デフォルトゲートウェイ | `192.0.2.1` | 必須。IPアドレスと同じネットワークの中のアドレス |
  | DNSサーバー | `192.0.2.53` | 1つか2つ。2つのときは空白で区切る |

  入力に誤りがあると、理由が表示され、入力をやり直せます。正しく入力すると、内容が表示され、`この内容で反映しますか? [y/N]:` と聞かれます。よければ `y` と入力してEnterを押します。

- 変更するのは、デフォルトゲートウェイにつながっているLAN端子1本だけです。ほかのLAN端子には触れません。
- 固定のIPアドレスだけを設定できます(自動取得(DHCP)は選べません)。
- 新しいIPアドレスは、手順11の結果の表示が終わってから3秒後に反映します。SSHで作業している場合は、その時点で接続が切れます。新しいIPアドレスで接続し直してください。

#### 3.3.3 手順11:結果の表示

最後に、次のような表示が出れば、導入は完了です。WebGUIの接続先を控えてください。

```
  デプロイが終わりました。

  WebGUIの接続先 :http://192.0.2.10:8080/
  初期アカウント :管理者 admin / パスワード admin
                  閲覧者 user  / パスワード なし(空欄)
```

#### 3.3.4 途中で失敗した場合

次のように、失敗した手順と原因が表示されて止まります。

```
!!! 手順 1(実行環境の確認…)で失敗しました。
!!! 原因:インターネットに接続できません(…)。ネットワークの設定を確かめてください
```

原因を取り除いてから、もう一度 `sudo bash deploy.sh` を実行してください。何度実行しても、登録した機器や設定は消えません。

## 4. 初回起動の確認

### 4.1 WebGUIにログインする

**手順1** 運用者のPCのブラウザで、3.3.3で控えた接続先(例:`http://192.0.2.10:8080/`)を開きます。

**手順2** ログインの画面で、ユーザー名に `admin`、パスワードに `admin` を入力して、ログインします。

**手順3** ダッシュボードが表示され、上部に「管理者のパスワードが初期パスワードのままです」と黄色の帯で表示されることを確かめます。

### 4.2 管理者のパスワードを変える(必ず行う)

初期アカウント(admin/admin、user/空欄)は、公開されている文書に載っている値です。**導入したら、必ず管理者のパスワードを変えてください。**

**手順1** 画面右上のユーザー名(`admin(管理者)`)を押します。パスワード変更の画面が開きます。

**手順2** 「現在のパスワード」に `admin`、「新しいパスワード」と「新しいパスワード(確認のため、もう一度)」に新しいパスワードを入力して、「変更する」を押します。

**手順3** ダッシュボードの黄色の帯が消えたことを確かめます。

閲覧者(user)は、パスワードが空欄のままでもログインできます。監視用のモニターにダッシュボードを常に表示しておく場合は、閲覧者でログインしておく運用にしてください。ログインはブラウザを閉じても続きます。

### 4.3 ダッシュボードの見方

| 表示 | 正常なとき |
| :---- | :---- |
| collectorの稼働状態 | 緑の「稼働中」 |
| Zabbixとの接続状態 | Zabbixを設定するまでは赤の「接続できない」。6章の設定のあとは緑の「接続中」 |
| 破棄件数 | Zabbixを設定するまでは「Zabbixに接続できない」が増えます。設定のあとは、すべて0 |

状態の色は、緑が正常、黄が注意、赤が異常、灰色が不明です。画面は10秒ごとに自動で更新されます。

## 5. Zabbixの準備

### 5.1 テンプレートファイルをPCに保存する

**手順1** 運用者のPCのブラウザで、次のページを開きます。

```
https://github.com/Panda-Taro/Zabbix_telemetry/tree/main/zabbix_templates
```

**手順2** `telemetry_nwsw.yaml` を押し、ファイルの中身が表示されたら、右上のダウンロードのボタン(Download raw file)を押して保存します。

**手順3** 同じように、`telemetry_collector.yaml` も保存します。

| ファイル | テンプレートの名前(表示名) | 適用先 |
| :---- | :---- | :---- |
| telemetry_nwsw.yaml | Telemetry NWSW用テンプレート | 各Nexusのホスト |
| telemetry_collector.yaml | Telemetry 中間サーバー用テンプレート | 「telemetry」ホスト |

### 5.2 テンプレートをZabbixに取り込む

**手順1** Zabbixの画面に管理者でログインします。

**手順2** 左のメニューで「データ収集」→「テンプレート」を開きます。

**手順3** 右上の「インポート」を押します。

**手順4** 「インポートするファイル」で、5.1で保存した `telemetry_nwsw.yaml` を選び、「インポート」を押します。確認が出たら「インポート」を押します。

**手順5** 同じように、`telemetry_collector.yaml` も取り込みます。

**手順6** テンプレートの一覧で、グループ「Templates/Telemetry」に、次の2つがあることを確かめます。

- Telemetry NWSW用テンプレート
- Telemetry 中間サーバー用テンプレート

テンプレートを更新したときも、同じ手順で取り込み直します。

### 5.3 「telemetry」ホストを登録する

中間サーバー自身の状態(受信件数、破棄件数など)を受け取るホストです。1つだけ登録します。

**手順1** 左のメニューで「データ収集」→「ホスト」を開き、右上の「ホストの作成」を押します。

**手順2** 次のように入力します。

| 項目 | 入力 |
| :---- | :---- |
| ホスト名 | `telemetry`(すべて小文字。1文字も変えないでください) |
| テンプレート | 「Telemetry 中間サーバー用テンプレート」を選ぶ |
| ホストグループ | 任意(例:新しく「Telemetry」と入力して作る) |
| インターフェース | 追加しなくて構いません |

**手順3** 「追加」を押します。

### 5.4 テンプレートに入っているもの

| テンプレート | 障害になる条件(トリガー) | 重要度 |
| :---- | :---- | :---- |
| NWSW用 | その機器からのTelemetryが途絶した(telemetry.statusが0) | 重度の障害 |
| NWSW用 | その機器の、特定のコマンドのTelemetryが途絶した(4コマンドそれぞれ) | 軽度の障害 |
| 中間サーバー用 | 中間サーバーのcollectorが停止した(3分間、値が届かない) | 重度の障害 |

- 機器全体が途絶している間は、コマンドごとの障害は出ません(障害は1件にまとまります)。
- 受信状態のアイテムは、1を「正常」、0を「途絶」と表示します。
- PTPの状態や帯域のしきい値(clock-stateがLocked以外、帯域の上限超えなど)のトリガーは、テンプレートに入っていません。必要に応じて、Zabbixの上で決めて追加してください。

## 6. 中間サーバーの全体設定

**手順1** WebGUIに管理者でログインし、左のメニューで「全体設定」を開きます。

**手順2** 「ZabbixサーバーのIPアドレス」にZabbix ServerのIPアドレス(例:`192.0.2.100`)を入力します。ポート番号を変えていなければ、ほかの項目は既定値のままで構いません。

**手順3** 「Zabbix接続テスト」を押し、接続できると表示されることを確かめます。

**手順4** 「保存する」を押します。

**手順5** ダッシュボードを開き、「Zabbixとの接続状態」が緑の「接続中」になることを確かめます(10秒ほどかかります)。

### 全体設定の項目

| 項目 | 既定値 | 受け付ける範囲 |
| :---- | :---- | :---- |
| ZabbixサーバーのIPアドレス | なし | 必須 |
| Zabbixサーバーのポート番号 | 10051 | 1〜65535 |
| Telemetryの受信ポート番号(UDP) | 50051 | 1024〜65535 |
| 途絶判定時間 | 300秒(5分) | 30〜3,600秒 |
| 自己監視値の送信間隔 | 60秒 | 10〜120秒 |
| LLD用データの定期送信間隔 | 3,600秒(1時間) | 300〜86,400秒 |
| 送信待ちキューの上限 | 100,000件 | 1,000〜1,000,000件 |
| ログレベル | INFO | DEBUG / INFO / WARNING / ERROR |

- 全体設定の変更は、中間サーバーを再起動せずに、10秒以内に反映します。
- Telemetryの受信ポート番号を変えると、受信が数秒止まります(保存の前に、その旨の確認が出ます)。変えた場合は、全Nexusの送信先のポート番号も変えてください。

## 7. 機器を追加するときの流れ

Nexusを1台追加するときは、次の順番で作業します。

```
(1) ホスト名を決める(Nexus・中間サーバー・Zabbix で、大文字・小文字まで同じにする)
(2) Zabbix     :ホストを登録し、テンプレートを適用する
(3) 中間サーバー:WebGUI で機器を登録する
(4) Nexus      :Telemetry の送信設定を入れる
(5) 中間サーバー:ダッシュボードで受信が始まったことを確かめる
(6) Zabbix     :アイテムが自動で作られ、値が記録されることを確かめる
```

### 7.1 ホスト名を決める

中間サーバーは、Nexusが送ってくるホスト名(Nexusの `hostname` の設定)で、どのZabbixのホストに値を送るかを決めます。**Nexus、中間サーバー、Zabbixの3か所で、ホスト名を大文字・小文字まで同じにしてください。** 以下では、例として `NEXUS-TEST-01` を使います。

### 7.2 Zabbixにホストを登録する

**手順1** Zabbixの画面で、「データ収集」→「ホスト」を開き、「ホストの作成」を押します。

**手順2** 次のように入力して、「追加」を押します。

| 項目 | 入力 |
| :---- | :---- |
| ホスト名 | `NEXUS-TEST-01`(7.1で決めたホスト名) |
| テンプレート | 「Telemetry NWSW用テンプレート」を選ぶ |
| ホストグループ | 任意 |
| インターフェース | 追加しなくて構いません |

### 7.3 中間サーバーに機器を登録する

**手順1** WebGUIに管理者でログインし、左のメニューで「機器一覧」を開き、「新規登録」を押します。

**手順2** 次のように入力します。

| 段階 | 項目 | 入力 |
| :---- | :---- | :---- |
| 1. 基本情報 | ホスト名 | `NEXUS-TEST-01`(7.1で決めたホスト名) |
| 1. 基本情報 | 送信元IPアドレス | NexusがTelemetryを送るときのIPアドレス(管理ポートmgmt0のIPアドレス。例:`192.0.2.21`) |
| 2. Zabbixへ送るコマンド | 4つのチェックボックス | Zabbixへ送るコマンドにチェックを入れる |
| 3. 監視対象インターフェース番号 | show interface counters brief 用(帯域) | 帯域を監視するポートの番号 |
| 3. 監視対象インターフェース番号 | show ptp brief 用(PTPポート状態) | PTPポート状態を監視するポートの番号 |

インターフェース番号の書き方:

| 書き方 | 意味 |
| :---- | :---- |
| `1/1` | スロット1のポート1(NexusのEthernet1/1) |
| `1/1, 1/2, 1/48` | カンマで区切って複数 |
| `1/1-4` | 範囲(1/1、1/2、1/3、1/4) |

- スロット番号は1〜99、ポート番号は1〜256です。
- ブレークアウトポート(`1/49/1` のような3段の番号)は監視できません。
- チェックを外したコマンドの入力欄は、入力できなくなります。

**手順3** 「保存する」を押します。10秒以内に、Zabbixへインターフェースの一覧(LLD用データ)が送られます。

### 7.4 NexusにTelemetryの送信設定を入れる

Nexusの設定は、運用者が行います。設定の例を示します。`<中間サーバーのIPアドレス>` と送信間隔は、実際の値に置き換えてください。送信間隔はミリ秒で指定します(例:10秒なら `10000`)。

```
telemetry
  destination-profile
    use-vrf management
  destination-group 200
    ip address <中間サーバーのIPアドレス> port 50051 protocol UDP encoding JSON
  sensor-group 300
    data-source NX-API
    path "show interface counters brief"
    path "show ptp brief"
    path "show ptp clock"
    path "show ptp parent"
  subscription 300
    dst-grp 200
    snsr-grp 300 sample-interval 10000
```

- 中間サーバーの全体設定でTelemetryの受信ポート番号を変えた場合は、`port 50051` もその番号にします。
- Telemetryは、管理ポート(mgmt0)を通る管理ネットワークで送ります(`use-vrf management`)。

### 7.5 中間サーバーで受信を確かめる

**手順1** WebGUIのダッシュボードを開きます。

**手順2** 「機器ごとの状態」で、登録した機器の受信状態が「受信待ち」から緑の「正常」に変わることを確かめます。

**手順3** 同じ行で、チェックを入れたコマンドの欄に、最終受信時刻が表示されることを確かめます。

| 表示 | 意味 |
| :---- | :---- |
| 時刻(緑) | 受信しています |
| 時刻(赤) | 最後の受信から、途絶判定時間が過ぎています |
| 未受信(黄) | まだ1度も受信していません |
| 対象外 | 機器の登録で、チェックを外したコマンドです |

**Telemetryの設定を入れた直後は、一部のコマンドが数分〜10分ほど届かないことがあります。** このとき、ダッシュボードではそのコマンドが「未受信」と表示されます。次の方法で、原因がNexus側か中間サーバー側かを確かめられます。

**手順A** Nexusで、次のコマンドを実行します。

```
show telemetry data collector details
```

**手順B** 表の中で、届いていないコマンドの行(右端のSensor Pathがそのコマンドの行)を見ます。

| 列 | 意味 |
| :---- | :---- |
| Successful | Nexusがデータを集めて送った回数 |
| Failed | 集めるのに失敗した回数 |
| Skipped | Nexusが集めずに飛ばした回数 |

**手順C** 1分ほど待ってから、もう一度同じコマンドを実行し、数字の増え方を比べます。

- **Skippedだけが増えている場合**:Nexusがそのコマンドのデータを集めていない状態です。中間サーバーの異常ではありません。しばらく待つとSuccessfulが増え始め、中間サーバーにも届き始めます。長く続く場合は、Nexusの設定や状態を確かめてください。
- **Successfulが増えているのに、中間サーバーで「未受信」のままの場合**:中間サーバー側か、途中の通信に原因があります。11.5を見てください。

### 7.6 Zabbixで値を確かめる

**手順1** Zabbixの画面で、「監視データ」→「最新データ」を開き、ホストに `NEXUS-TEST-01` を指定して表示します。

**手順2** 次のアイテムに値が入ることを確かめます。

- show ptp clock: clock-state、offset-from-master
- show ptp parent: gm-id
- show ptp brief: Ethernet1/1 stateなど(登録したインターフェースごと。自動で作られます)
- show interface counters brief: Ethernet1/1 inrate1、outrate1など(登録したインターフェースごと。自動で作られます)
- telemetry: 受信状態 など

インターフェースごとのアイテムは、中間サーバーから送られたインターフェースの一覧をもとに、Zabbixが自動で作ります。作られるまでの間(登録の直後)は、ダッシュボードの「Zabbix送信」の失敗件数が少し増えることがあります。

### 7.7 機器の登録を変える、削除する

- 監視対象インターフェースの追加・削除や、コマンドのチェックの変更は、WebGUIの「機器一覧」から機器を選んで行います。保存から10秒以内に反映し、Zabbixへインターフェースの一覧を送り直します。
- 一覧から外したインターフェースのアイテムは、Zabbixの設定(見つからなくなったリソースの扱い)に従って、Zabbix側で削除されます。
- 機器の登録を削除したり、コマンドのチェックを外したりすると、そのアイテムには値が届かなくなります。途絶の障害が残り続けた場合は、8.2の手順で手動で閉じてください。

## 8. 日常の運用

### 8.1 設定のバックアップを取る

中間サーバーが故障したときに備えて、**機器の登録内容を変えたら、そのたびにバックアップを取り、中間サーバーの外(運用者のPCなど)に保管してください。**

**手順1** WebGUIの左のメニューで「システム設定」を開きます。

**手順2** 「設定のバックアップ」の「バックアップファイルをダウンロード」を押し、ファイルを保存します。

- バックアップに入るのは、機器の登録内容と全体設定です。ユーザー、本体のIPアドレス、WebGUIのポート番号は入りません。
- 戻すときは、同じ画面の「設定の復元」でファイルを選び、「ファイルを確かめる」を押します。確認の画面で内容を確かめてから復元します。今の機器の登録内容と全体設定は、すべて置き換わります。
- 中間サーバーが故障した場合は、別のサーバーに3章の手順で導入し、バックアップから復元します。

### 8.2 残り続ける途絶の障害を手動で閉じる

機器の登録の削除や、コマンドのチェックを外したことで値が届かなくなったアイテムに、途絶の障害が残り続けることがあります。その場合は、Zabbixの画面で手動で閉じてください。

**手順1** Zabbixの画面で、「監視データ」→「障害」を開きます。

**手順2** 閉じたい障害の行の「更新」を押します。

**手順3** 「障害のクローズ」にチェックを入れ、「更新」を押します。

### 8.3 ログを見る

- WebGUIの左のメニューで「ログ」を開くと、「動作ログ」と「変更履歴」を見られます。日時やキーワードで絞り込み、表示している内容をダウンロードできます。
- 動作ログのファイルは、中間サーバーの `/data/logs/` にあります(collector.log、web.log)。

### 8.4 ユーザーを管理する

WebGUIの左のメニューで「ユーザー管理」を開くと、ユーザーの追加、権限の変更、削除、パスワードの初期化ができます。

| 権限 | できること |
| :---- | :---- |
| 管理者 | すべての画面 |
| 閲覧者 | ダッシュボードと、自分のパスワード変更だけ |

パスワードを初期化すると、管理者はユーザー名と同じ文字列、閲覧者は空欄になります。

## 9. 本体のIPアドレスとWebGUIのポート番号の変更

本体のIPアドレスとWebGUIのポート番号は、WebGUIの「システム設定」から変えられます。**変更は、中間サーバーの再起動で反映します。再起動の間(1〜2分程度)は、監視データが失われます。**

### 9.1 変更する前に

- **本体のIPアドレスを変える場合は、全Nexusの送信先(Telemetryの送信先のIPアドレス)と、Zabbix側の受け付け設定も変える必要があります。** たとえば、Zabbix Serverのファイアウォールで、中間サーバーのIPアドレスからの通信(TCP 10051)だけを通している場合は、その設定を新しいIPアドレスに変えてください。
- 再起動したくない時間帯には、変更自体を行わないでください。保存すると、すぐに再起動します。

### 9.2 変更の手順

**手順1** WebGUIに管理者でログインし、左のメニューで「システム設定」を開きます。

**手順2** 「本体のIPアドレスとWebGUIのポート番号」で、変えたい項目を入力します。

| 項目 | 決まり |
| :---- | :---- |
| IPアドレス/プレフィックス長 | プレフィックス長は8〜30 |
| デフォルトゲートウェイ | 必須。同じネットワークの中のアドレス |
| DNSサーバー(1つ目、2つ目) | 1つ以上、2つまで |
| WebGUIのポート番号 | 1024〜65535。ほかのプログラムが使っている番号は使えません |

IPアドレスを変えない場合は、IPアドレスの欄を今のままにしておきます。

**手順3** 「保存する」を押します。確認の画面が表示されます。

**手順4** 確認の画面で、変更する内容と「再起動のあとの接続先」を確かめ、接続先のURLを控えます。

- 変えてよければ「保存して再起動する」を押します。設定を保存し、すぐに中間サーバーを再起動します。
- やめる場合は「キャンセル」を押します。何も保存しません。

**手順5** 1〜2分待ってから、控えたURLをブラウザで開き、ログインできることを確かめます。

**手順6** 本体のIPアドレスを変えた場合は、全Nexusの送信先と、Zabbix側の受け付け設定を変えます。

### 9.3 新しいポート番号が使えなかった場合

再起動のあと、保存したWebGUIのポート番号が使えなかった場合は、WebGUIは既定値の **8080** で起動します。このとき、「システム設定」の画面にその旨が表示されます。`http://中間サーバーのIPアドレス:8080/` を開いてください。

## 10. 更新の方法

新しい版のソースコードを入れるときの手順です。**登録した機器、設定、ユーザー、ログは消えません。** 更新の途中でコンテナを作り直す間(通常は数十秒ほど)は、監視データが失われます。

**手順1** 中間サーバーにログインし(3.1)、ソースコードのフォルダに移動します。

```
cd ~/Zabbix_telemetry
```

**手順2** 新しいソースコードをダウンロードします。

```
git pull
```

フォルダを消してしまった場合は、3.2の手順でダウンロードし直してください。

**手順3** デプロイ用スクリプトを実行します。3章と同じように、NTPサーバーとIPアドレスを聞かれます。変えない場合は、どちらも何も入力せずにEnterを押します。

```
sudo bash deploy.sh
```

**手順4** Zabbixテンプレートが新しくなっている場合は、5.1と5.2の手順で取り込み直します。

## 11. 困ったとき

### 11.1 WebGUIに接続できない(ポート番号が分からない、間違えた)

中間サーバーのコンソールで、次のコマンドを実行します。WebGUIのポート番号を既定値の8080に戻し、WebGUIだけを起動し直します(Telemetryの受信は止まりません)。

```
sudo telemetry-recover reset-port
```

そのあと、`http://中間サーバーのIPアドレス:8080/` を開きます。

### 11.2 管理者のパスワードを忘れた

中間サーバーのコンソールで、次のコマンドを実行します。adminのパスワードが `admin` に戻ります。

```
sudo telemetry-recover reset-password
```

admin以外の管理者のパスワードを初期化する場合は、ユーザー名を付けます。パスワードはユーザー名と同じ文字列になります。

```
sudo telemetry-recover reset-password ユーザー名
```

- 指定したユーザーがいない、または管理者でない場合は、管理者の一覧が表示されて止まります。
- 管理者が1人もいない場合は、admin(パスワードはadmin)が作り直されます。
- 初期化したユーザーのログインは、すべて無効になります。
- この操作は、WebGUIの変更履歴に、ユーザー名「(復旧用コマンド)」として記録されます。

### 11.3 本体のIPアドレスを間違えて、接続できなくなった

本体のIPアドレスは、中間サーバーのコンソールで直します。

**手順1** 中間サーバーのコンソールにログインし、次のコマンドで、IPアドレスの設定ファイルの一覧を表示します。

```
ls /etc/netplan/
```

**手順2** 表示された中に `90-telemetry.yaml` があるかを見ます。

- **ある場合**(WebGUIまたはdeploy.shでIPアドレスを変えたことがある場合):中間サーバーのIPアドレスは、このファイルに書かれています。手順3へ進みます。
- **ない場合**:Ubuntuを入れたときの設定ファイル(例:`50-cloud-init.yaml`)に書かれています。手順3の `90-telemetry.yaml` を、そのファイルの名前に読み替えてください。

**手順3** 次のコマンドで、設定ファイルを開きます。

```
sudo nano /etc/netplan/90-telemetry.yaml
```

中身は、次のような形です(`eth0` の部分は、LAN端子の名前です)。

```
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: false
      addresses:
      - 192.0.2.10/24
      routes:
      - to: default
        via: 192.0.2.1
      nameservers:
        addresses:
        - 192.0.2.53
```

**手順4** 矢印キーで移動して、次の値を正しい値に書き換えます。行の先頭の空白(字下げ)は、変えないでください。

| 行 | 内容 |
| :---- | :---- |
| `addresses:` の下の `- 192.0.2.10/24` | IPアドレス/プレフィックス長 |
| `via: 192.0.2.1` | デフォルトゲートウェイ |
| `nameservers:` の下の `- 192.0.2.53` | DNSサーバー |

**手順5** `Ctrl` を押しながら `O` を押し、Enterを押して保存します。続けて `Ctrl` を押しながら `X` を押して、画面を閉じます。

**手順6** 次のコマンドで、書き換えた内容に誤りがないかを確かめます。

```
sudo netplan generate
```

`Error` を含む英語のメッセージが表示された場合は、書き方に誤りがあります。手順3からやり直し、字下げや記号を確かめてください。`Error` が表示されなければ、次へ進みます。

**手順7** 中間サーバーを再起動して、新しいIPアドレスを反映します。

```
sudo reboot
```

**手順8** 再起動のあと、新しいIPアドレスでWebGUIに接続できることを確かめます。

元の設定ファイルの控えは、`/var/lib/telemetry-hostctl/netplan-backup/` の中に、変更した日時ごとのフォルダに分けて残っています。

### 11.4 コンテナの状態を確かめたい

中間サーバーで、次のコマンドを実行します。

```
sudo docker ps
```

`telemetry-collector` と `telemetry-web` の2つが、`Up` と表示されていれば動いています。動いていない場合は、次のコマンドで原因を確かめます。

```
sudo docker logs --tail 50 telemetry-collector
sudo docker logs --tail 50 telemetry-web
```

collectorとwebは、異常終了しても自動で起動し直します。中間サーバーを再起動したときも、自動で起動します。

### 11.5 Nexusからデータが届かない

次の順番で確かめてください。

1. **WebGUIのダッシュボードの破棄件数を見る**
   - 「未登録の送信元」が増えている:機器の登録の送信元IPアドレスか、ホスト名が、Nexusと合っていません。ダッシュボードの「未登録の送信元」の一覧に、届いた送信元IPアドレスとホスト名が表示されます。
   - 「壊れたデータ」「4つ以外のコマンド」が増えている:Nexusの送信設定(encoding JSON、pathの書き方)を確かめてください。
2. **Nexusで `show telemetry data collector details` を見る**(7.5の手順A〜C)
3. **中間サーバーに届いているかを確かめる**:中間サーバーで次のコマンドを実行すると、30秒の間に届いたパケットを、コマンドごとに数えて表示します。

   ```
   sudo timeout 30 tcpdump -i any -nn -l -A udp port 50051 2>/dev/null | grep -a -o -E 'show (ptp (parent|clock|brief)|interface counters brief)' | sort | uniq -c
   ```

   何も表示されない場合は、Nexusからの通信が中間サーバーに届いていません。Nexusの送信先、途中のファイアウォール、中間サーバーのファイアウォールを確かめてください。

### 11.6 Zabbixに値が記録されない

- ダッシュボードの「Zabbixとの接続状態」が「接続できない」の場合:全体設定のZabbixサーバーのIPアドレスとポート番号を確かめ、「Zabbix接続テスト」を押してください。
- 「Zabbix送信」の失敗件数が増え続ける場合:Zabbixにホストが登録されていないか、ホスト名が違うか、テンプレートが適用されていません。7.2を確かめてください。

## 12. 付録

### 12.1 中間サーバーの中のファイルの場所

| 場所 | 内容 |
| :---- | :---- |
| `/data/telemetry.db` | 設定、ユーザー、変更履歴などのデータベース |
| `/data/logs/` | 動作ログ(collector.log、web.log) |
| `/etc/netplan/90-telemetry.yaml` | 本体のIPアドレスの設定(WebGUIまたはdeploy.shで変えた場合) |
| `/var/lib/telemetry-hostctl/netplan-backup/` | IPアドレスの設定を変える前の、元の設定ファイルの控え |
| `/usr/local/sbin/telemetry-recover` | 復旧用コマンド |
| `/usr/local/lib/telemetry-hostctl/` | 補助プログラム(本体のIPアドレスの書き換え、再起動、ファイアウォールの調整を行う) |

`/data` の中身は、更新やdeploy.shの再実行では消えません。ダウンロードしたソースコードのフォルダを消しても、中間サーバーと復旧用コマンドは動き続けます(更新のときは、ダウンロードし直してください)。

### 12.2 ファイアウォール(ufw)について

中間サーバーのファイアウォール(ufw)が有効な場合は、deploy.shと補助プログラムが、次のポートを自動で開けます。

- WebGUIのポート番号(TCP)と、8080/tcp(常に開けておきます。9.3の場合に備えるため)
- Telemetryの受信ポート番号(UDP)

ポート番号を変えた場合は、新しい番号を開け、古い番号を閉じます。ファイアウォールが無効な場合は、何もしません。

### 12.3 Zabbixのアイテムのキー

| アイテムのキー | 内容 |
| :---- | :---- |
| `show.ptp.clock.clock-state` | ロック状態(例:Locked) |
| `show.ptp.clock.offset-from-master` | Offset from Master(ns) |
| `show.ptp.parent.gm-id` | GM-ID |
| `show.ptp.brief.state[1/1]` | PTPポート状態(インターフェースごと) |
| `show.interface.counters.brief.inrate1[1/1]` | 入力帯域(bps。インターフェースごと) |
| `show.interface.counters.brief.outrate1[1/1]` | 出力帯域(bps。インターフェースごと) |
| `telemetry.status` | 機器の受信状態(1=正常、0=途絶) |
| `telemetry.age` | 最後の受信からの経過秒数 |
| `telemetry.status[show ptp clock]` など | コマンドごとの受信状態(1=正常、0=途絶) |

帯域は、Nexusの表示(MB/秒)を8,000,000倍して、bps(ビット/秒)で送ります。Zabbixは、自動でMbpsやGbpsに読み替えて表示します。
