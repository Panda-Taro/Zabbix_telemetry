# 模擬送信ツールの使い方

## 1. このツールでできること

模擬送信ツール(`tools/telemetry_simulator.py`)は、Cisco Nexus の代わりに、Telemetry のデータを中間サーバーへ送る検証用のツールです。実機の Nexus をつながなくても、中間サーバーと Zabbix の動作を確かめられます。

- `tests/fixtures/` にある4つのテストデータ(架空の値に置き換えたもの)をもとに、UDP で送ります。
- 送るコマンドは、次の4つです。
  - show interface counters brief
  - show ptp brief
  - show ptp clock
  - show ptp parent
- 台数、送信間隔、ホスト名、送信元、送信先を指定して、複数台分を同時に送れます。
- 壊れたデータ、4つ以外のコマンド、値が欠けたデータなど、異常なデータも送れます。

このツールは Python 3 の標準の機能だけで動きます。追加のライブラリは要りません。

## 2. 準備

### 2.1 中間サーバー(Ubuntu Server)で使う場合

Ubuntu Server 24.04 LTS には、最初から Python 3 が入っています。ソースコード一式をダウンロードしたフォルダに移動してから、コマンドを入力します。

```
cd ソースコード一式のフォルダ
python3 tools/telemetry_simulator.py --help
```

使い方の説明が表示されれば、準備は完了です。

### 2.2 Windows のPCで使う場合

Python 3 を入れたPCで、ソースコード一式のフォルダに移動してから、次のように入力します。

```
py tools\telemetry_simulator.py --help
```

この場合、送信元はそのPCのIPアドレスになります。中間サーバーのWebGUIには、そのPCのIPアドレスを、機器の送信元IPアドレスとして登録してください。

## 3. 基本の使い方

以下の例の `192.0.2.100` は、中間サーバーのIPアドレスの例です。実際の中間サーバーのIPアドレスに置き換えてください。

### 3.1 1台分を、10秒ごとに送り続ける

```
python3 tools/telemetry_simulator.py --target 192.0.2.100
```

- ホスト名は `NEXUS-TEST-01` になります。
- 止めるときは、キーボードの `Ctrl` を押しながら `C` を押します。

### 3.2 1回だけ送る

```
python3 tools/telemetry_simulator.py --target 192.0.2.100 --count 1
```

### 3.3 ホスト名を指定して送る

```
python3 tools/telemetry_simulator.py --target 192.0.2.100 --hostnames NEXUS-TEST-05
```

### 3.4 送るコマンドを選ぶ

```
python3 tools/telemetry_simulator.py --target 192.0.2.100 --commands ptp-clock,ptp-parent
```

## 4. 指定できる項目

| 指定 | 内容 | 既定値 |
| :---- | :---- | :---- |
| `--target` | 送信先(中間サーバー)のIPアドレス。**必ず指定します** | なし |
| `--port` | 送信先のUDPポート番号。中間サーバーの全体設定の「Telemetryの受信ポート番号」と合わせます | 50051 |
| `--devices` | 模擬する台数 | 1 |
| `--hostname-format` | ホスト名の付け方。`{n}` に番号が入ります | `NEXUS-TEST-{n:02d}`(NEXUS-TEST-01、02 …) |
| `--start-number` | ホスト名の番号の始まり | 1 |
| `--hostnames` | ホスト名をカンマ区切りで直接指定します。数は台数と同じにします | なし |
| `--source-ips` | 機器ごとの送信元IPアドレス(5章) | このPCのIPアドレス |
| `--interval` | 1台あたりの送信間隔(秒) | 10 |
| `--count` | 1台あたりに送る回数。0 は止めるまで送り続けます | 0 |
| `--duration` | 送り続ける時間(秒)。0 は制限なし | 0 |
| `--commands` | 送るコマンド。`counters`、`ptp-brief`、`ptp-clock`、`ptp-parent` をカンマ区切りで指定します | 4つすべて |
| `--ports` | show interface counters brief と show ptp brief の行を、Ethernet1/1〜1/指定した数 にそろえます(最大256) | テストデータのまま |
| `--abnormal` | 異常なデータを送ります(6章) | なし |
| `--no-header` | 実機が付けるヘッダーの代わりのバイト列を付けずに送ります | 付ける |
| `--quiet` | 1回ごとの表示をしません | 表示する |

- 1回送るごとに、指定したコマンドの数だけパケットを送ります(4コマンドなら4パケット)。
- 複数台分を送るときは、全台が同じ瞬間に送らないよう、送り始めを送信間隔の中で散らします。

## 5. 複数台分を送る

### 5.1 送信元IPアドレスが台数分必要な理由

中間サーバーは、届いたデータの送信元IPアドレスで、どの機器のデータかを見分けます。このため、複数台分を送るときは、台数分の送信元IPアドレスが必要です。

`--source-ips` で、機器ごとの送信元IPアドレスを指定します。

| 書き方 | 意味 |
| :---- | :---- |
| `192.0.2.11` | 1つ |
| `192.0.2.11,192.0.2.12` | カンマ区切り |
| `192.0.2.11-192.0.2.60` | 範囲(50個) |
| `192.0.2.11-60` | 範囲の短い書き方(上と同じ) |

指定したIPアドレスは、ツールを動かすPCに設定されている必要があります。

### 5.2 中間サーバーに、試験用のIPアドレスを一時的に追加する

中間サーバーの上でツールを動かす場合は、試験用のIPアドレスを一時的に追加して、送信元に使えます。ここでは、文書用に決められている範囲(192.0.2.0/24)のアドレスを使います。

**手順1** 中間サーバーのコンソールで、試験用の仮の接続口(sim0)を作ります。

```
sudo ip link add sim0 type dummy
sudo ip link set sim0 up
```

**手順2** 試験用のIPアドレスを、台数分追加します。10台分(192.0.2.11〜192.0.2.20)の場合は、次のとおりです。

```
for i in $(seq 11 20); do sudo ip addr add 192.0.2.$i/32 dev sim0; done
```

50台分(192.0.2.11〜192.0.2.60)の場合は、`seq 11 20` を `seq 11 60` に変えます。

**手順3** ツールで10台分を送ります。`--target` には、中間サーバー自身のIPアドレスを指定します。

```
python3 tools/telemetry_simulator.py --target 中間サーバーのIPアドレス --devices 10 --source-ips 192.0.2.11-20
```

**手順4** 試験が終わったら、仮の接続口を削除します。追加したIPアドレスも一緒に消えます。

```
sudo ip link delete sim0
```

- 中間サーバーを再起動した場合も、仮の接続口は消えます。
- 中間サーバーの本来のネットワーク設定には影響しません。

### 5.3 WebGUIへの機器の登録

送ったデータを中間サーバーが受け付けるのは、WebGUIで登録した機器だけです。ツールで送るホスト名と送信元IPアドレスの組を、WebGUIで登録してください。

| ホスト名 | 送信元IPアドレス |
| :---- | :---- |
| NEXUS-TEST-01 | 192.0.2.11 |
| NEXUS-TEST-02 | 192.0.2.12 |
| … | … |
| NEXUS-TEST-10 | 192.0.2.20 |

テストデータに含まれるインターフェース番号は、次のとおりです。監視対象インターフェースには、この中から選んで登録してください。

- show interface counters brief:1/1〜1/54(帯域が0でないのは 1/3〜1/8 です。それ以外は0が送られます)
- show ptp brief:1/1、1/3〜1/9、1/21(`--ports` を指定した場合は 1/1〜指定した数)

## 6. 異常なデータを送る

`--abnormal` に、次のどれかを指定します。

| 指定 | 送るデータ | 中間サーバーでの扱い(正しい動作) |
| :---- | :---- | :---- |
| `broken` | JSONの途中で切れたデータ | 「壊れたデータ」として破棄され、件数が増える |
| `unknown-command` | 4つ以外のコマンド(show ptp clock detail など) | 「4つ以外のコマンド」として破棄され、件数が増える |
| `missing-values` | 値の項目がないデータ(clock-state、gm-id、state、eth_inrate1 など) | その値はZabbixへ送られない(0は送られない) |
| `na-values` | 数値として読めない値(offset-from-master、eth_inrate1 などが「N/A」) | その値はZabbixへ送られない |

例:壊れたデータを1回だけ送る

```
python3 tools/telemetry_simulator.py --target 192.0.2.100 --count 1 --abnormal broken
```

このほか、次のような送り方でも、異常時の動作を確かめられます。

- **登録していないホスト名で送る**(ホスト名の不一致):`--hostnames NEXUS-TEST-99` のように、WebGUIの登録と違うホスト名を指定します。
- **登録していない送信元から送る**:WebGUIに登録していない送信元IPアドレスから送ります。

## 7. 10台で負荷をかける

台数を10台にしたまま、送信間隔を短くして負荷をかけます。5.2の手順で、試験用のIPアドレスを10個(192.0.2.11〜192.0.2.20)追加し、5.3のとおり10台を登録してから行います。

### 7.1 1秒あたりのパケット数の求め方

ツールは、1台ごとに、送信間隔ごとに、指定したコマンドの数だけパケットを送ります。

```
1秒あたりのパケット数 = 台数 × コマンドの数 ÷ 送信間隔(秒)
```

### 7.2 送り方の例

以下の例は、どれも10分間(600秒)送り続けます。`中間サーバーのIPアドレス` は、実際のアドレスに置き換えてください。

**例1 10台・0.1秒間隔・帯域のみ・54ポート(100パケット/秒)**

```
python3 tools/telemetry_simulator.py --target 中間サーバーのIPアドレス --devices 10 --source-ips 192.0.2.11-20 --interval 0.1 --ports 54 --commands counters --duration 600 --quiet
```

- 10台 × 1コマンド ÷ 0.1秒 = **100パケット/秒**
- show interface counters brief だけを送ります。1パケットに54ポート分の帯域が入ります。

**例2 10台・0.4秒間隔・4コマンド・54ポート(100パケット/秒)**

```
python3 tools/telemetry_simulator.py --target 中間サーバーのIPアドレス --devices 10 --source-ips 192.0.2.11-20 --interval 0.4 --ports 54 --duration 600 --quiet
```

- 10台 × 4コマンド ÷ 0.4秒 = **100パケット/秒**
- 4つのコマンドをすべて送ります。

**例3 10台・0.1秒間隔・4コマンド・54ポート(400パケット/秒)**

```
python3 tools/telemetry_simulator.py --target 中間サーバーのIPアドレス --devices 10 --source-ips 192.0.2.11-20 --interval 0.1 --ports 54 --duration 600 --quiet
```

- 10台 × 4コマンド ÷ 0.1秒 = **400パケット/秒**
- 要件の性能の目標(100パケット/秒)の4倍の負荷です。余裕を確かめたいときに使います。

### 7.3 Zabbixへ送る値の数

1秒あたりにZabbixへ送る値の数は、WebGUIで登録した監視対象インターフェースの数で決まります。帯域のインターフェースを54ポート登録した場合、1パケットあたり108個(54ポート × 入力・出力)の値になります。

| 送り方 | Zabbixへ送る値の数(1秒あたり、帯域54ポート・PTP1ポートを登録した場合) |
| :---- | :---- |
| 例1 | 約10,800件 |
| 例2 | 約2,800件 |
| 例3 | 約11,200件 |

- 要件の性能の目標は、Zabbixへの送信が2,000件/秒です(要件定義書の11.1.2)。どの例も、これを超える負荷になります。
- Zabbixの処理が追いつかない場合は、送信待ちキューが満杯になり、「送信待ちキューが満杯」の破棄件数が増えます。
- 結果を見るときは、ダッシュボードの「破棄件数」と「送信待ちキュー」を確かめてください。

## 8. 結合テスト(要件定義書の12.3)での使い方の例

| テスト番号 | 使い方の例 |
| :---- | :---- |
| T2-06 値の記録 | `--target 中間サーバーのIPアドレス --count 1` |
| T2-15 未登録の送信元 | WebGUIに登録していないPCから、`--count 1` で送る |
| T2-16 ホスト名の不一致 | `--count 1 --hostnames NEXUS-TEST-99` |
| T2-17 壊れたデータ、4つ以外のコマンド | `--count 1 --abnormal broken`、`--count 1 --abnormal unknown-command` |
| T2-22 途絶の検知 | 送り続けている状態で `Ctrl` + `C` で止め、途絶判定時間(既定値5分)待つ |
| T2-43 想定負荷(10台) | `--devices 10 --source-ips 192.0.2.11-20 --interval 10 --ports 54` |
| T2-44 性能の目標(100パケット/秒) | 7.2の例1または例2 |

## 9. 注意

- このツールは検証用です。運用中の中間サーバーに送ると、Zabbixに試験の値が記録されます。
- 送るデータの値(帯域、PTPの状態など)は、テストデータの値そのものです。毎回同じ値を送ります。
- 送ったデータのNexus側の時刻(msg_timestamp など)は、送った時刻に書き換えます。中間サーバーはこの時刻を使わず、受信した時刻を記録します。
